# Iteration 4 — Refinement & Intelligence

## Intent
Explore enhancements that improve Ember’s usefulness without compromising
its quiet, respectful nature.

## Context & Constraints
- All previous iterations must feel stable
- Power discipline remains non‑negotiable
- Complexity should be earned, not added by default

## Assumptions
- Some intelligence can be added without constant activity
- Users value calm behavior over responsiveness
- Not all ideas belong in the device

## Design Decisions
- Add features selectively and experimentally
- Treat intelligence as optional, not core
- Continuously evaluate impact on Ember’s personality

## Explicit Non‑Goals
- No feature parity with commercial assistants
- No continuous background processing
- No attention‑seeking behavior

## Implementation Notes
- Enhancements are prototyped behind clear boundaries
- Features may be removed if they feel wrong
- Observability is prioritized over polish

## Risks & Open Questions
- When does intelligence become noise?
- How much autonomy should Ember have?
- What features violate Ember’s core principle?

## Reflection
Not everything that is possible is appropriate.
This iteration is about saying “no” well.
